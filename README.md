## 🗄️ Banco de dados, login e perfil

O Quiz agora exige login. Contas, perfis, ranking e emblemas ficam salvos no banco SQLite `quiz.db`,
que a API (`app.py`) cria sozinha na primeira vez que roda. No navegador fica salvo só o token da sessão.

Como rodar:

1.  `pip install flask`
2.  `python app.py` (a API sobe em http://127.0.0.1:5000)
3.  Abra o `index.html` (de preferência com o Live Server do VS Code).

O que existe:

-   Cadastro e login por e-mail ou nickname, com nickname único (✓ livre / ✗ em uso), foto, banner e biografia.
-   Aba **Perfil**: ranking, pontuações, Top, emblemas, alterar nickname e senha (uma vez a cada 7 dias) e excluir a conta.
-   Emblemas: GennisAccount, GoogleAccount, Top 1, Top 2 e Top 3.
-   Excluir a conta apaga tudo da pessoa do banco.

Login com Google (opcional, precisa de configuração — passo a passo completo em **LOGIN_GOOGLE.md**):

1.  Em console.cloud.google.com crie um projeto e, em "APIs e serviços > Credenciais", um **ID do cliente OAuth** do tipo "Aplicativo da Web".
2.  Em "Origens JavaScript autorizadas" coloque `http://localhost:5000` (não use 127.0.0.1: o Google recusa IP) e, na Vercel, o endereço `https://...vercel.app`.
3.  Antes de rodar a API, defina a variável `GOOGLE_CLIENT_ID` com esse ID (ou escreva no `app.py`).
4.  Sem isso, o botão do Google fica desativado e o resto funciona normalmente.

## Atualização: perguntas novas, pontuação acumulada e modo Radical

- **Perguntas novas:** cada modo tem as suas 15 perguntas (45 no total, em `PERGUNTAS_POR_MODO` no `script.js` e na lista `perguntas` do `app.py`). No modo Difícil as perguntas mostram um trecho de código (Python, Java ou SQL) em um bloco próprio, com campos `linguagem` e `codigo`. As perguntas antigas foram removidas.
- **Ranking por pontos acumulados:** cada acerto soma pontos: **Fácil +10, Normal +20, Difícil +30**. O ranking de cada modo (e o Geral, que soma todos) é a soma dos pontos de todas as partidas do jogador, então a posição e o Top 1, 2 e 3 mudam conforme a pessoa joga. Os pontos ficam na tabela `ranking` (coluna `pontos`, uma linha por partida), aparecem no perfil (pontos totais e por modo) e na API (`GET /ranking` devolve `pontos` e `partidas`). Empate: fica na frente quem chegou na pontuação primeiro.
- **Banco antigo:** ao abrir o `app.py`, o banco existente é migrado sozinho (a tabela `ranking` é refeita com a coluna `pontos` e o modo `radical`). As partidas antigas entram com os pontos já calculados (acertos x valor do modo) e nada é perdido. Faça uma cópia do `quiz.db` antes, por garantia.
- **Modo Radical:** junta as 45 perguntas, sorteia 15 (ordem e alternativas embaralhadas a cada partida) e a dica de cada pergunta segue o nível dela. Cada acerto vale os pontos do nível (+10, +20 ou +30) e o tempo muda por pergunta: **Fácil 30s, Normal 20s, Difícil 15s**. Toda vez que o jogador escolhe o Radical aparece um pop-up avisando que as perguntas são aleatórias, com os botões **Sim** e **Não**. O Radical tem o próprio filtro no ranking.
- **API:** `GET /api/perguntas?modo=facil|normal|dificil|radical` (o radical devolve 15 sorteadas); `POST /ranking` aceita `modo: "radical"` com `acertos_por_nivel` (`{"facil": n, "normal": n, "dificil": n}`) e a API calcula os pontos. O navegador nunca manda a pontuação pronta.
- `doc_date/08-extensao` foi atualizado com a coluna `pontos` e as consultas do ranking por soma de pontos.


## Atualização: banco PostgreSQL e publicação no Render

O banco passou de SQLite (`quiz.db`) para **PostgreSQL**, porque o Render (e a Vercel) não guardam arquivos: um `quiz.db` lá se perderia a cada reinício. O resto do código e da estrutura continua igual (as rotas, o `script.js` e as tabelas são os mesmos). O que mudou:

- `app.py`: usa `psycopg2` e lê o banco da variável **`DATABASE_URL`**. As consultas continuam escritas do mesmo jeito (a classe `Banco` faz a ponte). Só o que era específico do SQLite foi trocado (`AUTOINCREMENT`, `INSERT OR IGNORE`, `GLOB`, `instr`, `PRAGMA`, `lastrowid`). As tabelas são criadas sozinhas na primeira execução.
- A **chave dos logins** não pode mais ficar num arquivo (o disco do Render é apagado a cada deploy). Defina **`GENNISQUIZ_SECRET`** (qualquer texto longo e secreto). Sem ela, todo mundo seria deslogado a cada reinício.
- Arquivos novos: `requirements.txt`, `render.yaml` (opcional), `.gitignore` e `migrar_sqlite_para_postgres.py` (leva os dados do `quiz.db` atual).
- `script.js`: no começo tem `API_RENDER`; troque pelo endereço do seu Web Service no Render se o site ficar em outro domínio (ex.: `gennisquiz.vercel.app`). Aberto pelo próprio Render, ele já usa o mesmo endereço.

### Passo a passo no Render

1.  Suba o projeto no GitHub (o `.gitignore` já deixa `quiz.db` e `quiz_secret.key` de fora: eles têm e-mails e senhas em hash, não publique).
2.  No Render: **New > PostgreSQL** (nome `gennisquiz-db`). Quando ficar pronto, copie a **Internal Database URL** e a **External Database URL**.
3.  **New > Web Service**, escolha o repositório e preencha:
    -   Build Command: `pip install -r requirements.txt`
    -   Start Command: `gunicorn app:app --workers 2 --threads 4 --timeout 60`
    -   Environment: `DATABASE_URL` = a **Internal Database URL**; `GENNISQUIZ_SECRET` = um texto secreto longo; (opcional) `GOOGLE_CLIENT_ID` e `QUIZ_DONO_EMAIL`.
    -   (Atalho: **New > Blueprint** usa o `render.yaml` e cria o PostgreSQL e o Web Service juntos.)
4.  Abra o endereço do Web Service (`https://....onrender.com`): o Quiz já abre por ele, porque o Flask entrega o site.
5.  **Levar os dados atuais** (opcional, faça uma vez, no seu computador, com o `quiz.db` na pasta):
    ```
    pip install flask psycopg2-binary
    set DATABASE_URL=<External Database URL>        (Linux/Mac: export DATABASE_URL=...)
    python migrar_sqlite_para_postgres.py
    ```
    Usuários, senhas (hash), fotos, partidas, pontos e emblemas são copiados com os mesmos ids. O `quiz.db` não é alterado.
6.  **Se o site continuar na Vercel:** ajuste `API_RENDER` no `script.js` e, se usar o login com Google, acrescente `https://gennisquiz.vercel.app` (e o endereço do Render) em "Origens JavaScript autorizadas" no Google Cloud.

Para rodar no computador agora é preciso ter um PostgreSQL: `pip install -r requirements.txt`, crie um banco chamado `quiz` e defina a `DATABASE_URL` (ex.: `postgresql://postgres:SENHA@localhost:5432/quiz`) antes de `python app.py`.
No plano gratuito do Render, o serviço pode demorar um pouco na primeira visita depois de ficar parado.


## Atualização: painel do desenvolvedor zera e muda pontos

Quem tem acesso ao painel (emblema Dono ou Desenvolvedor) agora vê a seção **Pontos** ao editar um usuário:

- **Modo Fácil, Normal e Difícil**: dá para definir um valor novo ou zerar. O valor precisa ser múltiplo do modo (fácil de 10 em 10, normal de 20 em 20, difícil de 30 em 30). Tem também o botão **Zerar todos os modos**.
- O **modo Radical não entra**, porque ele sorteia perguntas de todos os níveis.
- Os ajustes ficam salvos no PostgreSQL, na tabela `ajuste_pontos` (um por jogador e por modo, guarda a diferença em relação às partidas), e saem pela API `PUT /api/dev/usuarios/<nickname>/pontos` com `{"modo": "facil|normal|dificil|todos", "pontos": 0}` (`todos` só aceita 0). O histórico de partidas não é apagado.
- Os ajustes entram no ranking (por modo e geral), no perfil e nos emblemas Top 1, 2 e 3. Depois do ajuste o jogador continua somando pontos normalmente.
- Só um dono mexe nos pontos da conta de outro dono. A tabela é criada sozinha ao iniciar o app; o `migrar_sqlite_para_postgres.py` não precisa de mudança.
